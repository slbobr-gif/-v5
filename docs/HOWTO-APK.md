# Как получить APK «Путника» v5 и раздать друзьям

APK собирает GitHub. На компьютер ничего ставить не нужно.

## Сборка: новый репозиторий (рекомендую)

Старый репозиторий лучше не обновлять: в нём остались файлы прошлой версии, и проверки упадут.

1. github.com → **+** → **New repository** → имя `putnik-v5` → **Private** → **Create repository** (галочки README и .gitignore не ставь).
2. Распакуй архив `putnik-v5.3-upload.zip` → внутри папка `putnik-v5.3-upload` с шестью папками «Порция 1» … «Порция 6».
3. Загружай **по порциям, по порядку**. Каждый раз: открой папку «Порция N», выдели **всё её содержимое** (не саму папку) → **Add file → Upload files** (в пустом репозитории — ссылка **uploading an existing file**) → перетащи → **Commit changes**. GitHub сам разложит файлы по папкам `app/…`, `tools/…`.
   * Порция 1 — код приложения (`app` без картинок, `.gitignore`, `README.md`);
   * Порция 2 — иконки предметов, зон, вкладок, героя;
   * Порция 3 — остальные картинки и контент;
   * Порция 4 — `tools`, `content`, `infra`;
   * Порция 5 — `docs`, `backend`, `.claude` (включи показ скрытых файлов: Windows — Проводник → Вид → Показать → Скрытые элементы; Mac — Cmd+Shift+Точка);
   * Порция 6 — `.github` (сборка). Если папка не перетаскивается: **Add file → Create new file**, имя `.github/workflows/android.yml`, вставь содержимое файла из порции 6 → **Commit changes**.
   * **Проверь после загрузки:** в корне репозитория нет папок «Порция …» (если есть — ты перетащил саму папку; удали её и загрузи содержимое), а в `app/pubspec.yaml` четвёртая строка — версия новой сборки. Загружай **все шесть порций** каждой новой версии: смесь старых и новых порций ломает проверку контента.
4. Вкладка **Actions** → если просит, **I understand my workflows, go ahead and enable them** → сборка **Android** запустится сама после порции 6 (или **Android → Run workflow**).
5. Через 12–15 минут APK лежит без архива по постоянной ссылке (открой её прямо на телефоне):
   `https://github.com/slbobr-gif/-v5/releases/latest/download/putnik-test.apk`
   Запасной путь: запуск с зелёной галочкой → внизу **Artifacts** → **putnik-apk**. Это **zip-архив**: сначала распакуй, ставь `putnik-test.apk` из него. Сам `.zip` Android не установит («пакет недействителен»).

## Подключить аналитику (5 минут, нужно для теста)

Без ключа приложение работает, но статистика остаётся только на телефонах — ты не увидишь, кто сколько прошёл.

1. Зайди на **appmetrica.yandex.ru** (вход через Яндекс ID) → **Добавить приложение** → платформа Android, название «Путник».
2. В настройках приложения скопируй **Ключ API** (строка вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`).
3. На GitHub: репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**. Имя: `APPMETRICA_KEY`, значение — ключ. **Add secret**.
4. Запусти сборку заново (**Actions → Android → Run workflow**). Новый APK будет отправлять статистику.

Проверить: в приложении **Настройки → О приложении** — строка «Статистика отправляется в AppMetrica».

## Установка на телефон друга

1. Отправь файл `putnik-test.apk` в Telegram (личным сообщением или в чат теста).
2. Друг открывает файл → Android спросит «Разрешить установку из этого источника» → разрешить → **Установить**.
3. При первом запуске: имя, почта (по желанию), согласие → разрешение **«Физическая активность»** (без него шаги не считаются) → по желанию Health Connect и уведомления → пролог → путь начался.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Приложение открывается и сразу закрывается | Запусти ещё раз: откроется экран «Путник упал при прошлом запуске» с текстом ошибки → **Скопировать** или **Отправить** → пришли мне. Ещё быстрее: в GitHub открой запуск сборки → задача **Запуск на эмуляторе** → на странице запуска будет блок с журналом падения |
| Сборка красная | Открой упавший шаг → скопируй последние 40 строк лога → пришли мне |
| Шаг «Карта по реальным данным» красный | Не страшно: собралось с резервной картой. Можно перезапустить позже |
| «Проверки и тесты» красные, а APK есть | APK рабочий; пришли лог проверок — поправлю |
| Системное окно Xiaomi «Отправить отчёт» с `NoSuchMethodException … WorkDatabase_Impl` | Исправлено в v5.2 (оптимизатор R8 вырезал часть WorkManager). Обнови папку `app` и пересобери |
| Шаги не идут | Настройки приложения → Шагомер телефона → «Разрешить». На Xiaomi/Huawei/Honor: настройки батареи → «Путник» → без ограничений |
| Шагов меньше, чем в фитнес-приложении | Подключи Health Connect: тогда берётся максимум из обоих источников |
| Телефон пишет «приложение не установлено» | Один раз удали старую тестовую версию (из прошлой сборки этапа 1 — у неё другая подпись). Дальше все новые сборки v5 ставятся поверх и сохраняют прогресс |

## Что внутри сборки

* Главы 1–2 полностью: Москва → Тверь → Великий Новгород, ≈ 570 км пути Сергея. После Новгорода путь продолжается до Териберки со случайными событиями, рынками и утренними мыслями; сюжет глав 3–6 — в следующих обновлениях.
* 1 реальный шаг = 5 шагов Сергея (3,75 м). При 7 000 шагах в день глава 1 занимает около недели, глава 2 — ещё две.
* Шаги: встроенный шагомер телефона (в фоне раз в 15 минут) + Health Connect, берётся максимум.
* Без сервера: всё хранится на телефоне. Удаление приложения удаляет прогресс, обновление поверх — сохраняет (все сборки подписаны одним тестовым ключом).
* Точность дня шагов: если телефон не даёт читать шагомер в фоне, шаги засчитаются при следующем открытии приложения (иногда в другой день). С Health Connect дни всегда точные — советуй друзьям подключить его.
