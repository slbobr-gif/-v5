# Этап 0 · Архитектура MVP v5 (офлайн)

Ведёт: Архитектор. Подключены: Картограф, Геймдизайнер, Квест-архитектор, DevOps.

## 1. Принципы

* **Всё на телефоне.** Сервера нет. Контент (`assets/content/*.json`), баланс (`assets/balance.json`) и карта (`assets/map/map.json`) вшиты в APK. Обновление — новой сборкой.
* **Один движок, одна правда.** Вся игровая логика — чистый Dart в `lib/engine/` без Flutter-импортов. Её эталон — Python-движок `tools/sim/engine.py`, на котором прогоняется симулятор баланса. Правила в обоих совпадают построчно.
* **Детерминизм.** Случайности движка идут от seed в состоянии героя. Одинаковые шаги и выборы дают одинаковый результат — это позволяет воспроизводить жалобы тестировщиков.
* **Шаги — только по факту.** Движок получает «шагов за локальный день» из шагомера и сам считает прирост. Повторный и запоздалый замер ничего не ломает (максимум по дню, как на сервере в этапе 0).

## 2. Слои клиента

```
app/lib/
  engine/            — чистый Dart: модели, движок пути, события, экономика, смерть, погода
  data/              — загрузка контента/баланса/карты из assets, сохранение состояния (SharedPreferences, JSON)
  platform/          — каналы к Kotlin: шаги (датчик + Health Connect), уведомления
  analytics/         — AppMetrica + локальный журнал событий
  app/               — состояние приложения (Riverpod), связывает движок, данные, платформу
  ui/                — экраны и виджеты (только отображение и вызовы app/)
  l10n/              — строки интерфейса (.arb, RU; ключи готовы для EN/ZH)
android-overlay/     — Kotlin-код и манифест, накладываются на сгенерированный android/
```

Правило зависимостей: `ui → app → engine/data/platform/analytics`; `engine` не импортирует ничего, кроме `dart:` и своих файлов.

## 3. Шаги с телефона

Два источника, берётся максимум по каждому дню:

1. **Датчик шагов телефона** (`TYPE_STEP_COUNTER`). Работает на любом телефоне со встроенным шагомером, сторонние приложения не нужны. Счётчик живёт в железе с момента включения телефона. Kotlin-задача WorkManager раз в 15 минут (и при каждом открытии приложения) читает счётчик и раскладывает прирост по локальным дням. Перезагрузка телефона определяется по уменьшению счётчика и времени загрузки. Нужно разрешение «Физическая активность».
2. **Health Connect** (если есть на телефоне и пользователь разрешил): шаги по дням за последние 30 дней из всех приложений (Samsung Health, Mi Fitness, Google Fit, часы и браслеты). Даёт историю «до установки» и шаги с часов.

Ограничение датчика: шаги до установки приложения он не знает. Поэтому стартовый день начинается с нуля, а Health Connect, если есть, добавляет историю. В игру засчитываются шаги **начиная с дня старта путешествия**.

## 4. Петля обновления

При открытии приложения и раз в 15 минут в фоне (только датчик, без движка):

```
шагомер → {день: шагов} → engine.syncSteps() → прирост реальных шагов → ×3,75 м → buffer
engine.advance(now) → герой идёт до ближайшей остановки (событие, город, конец главы),
                      тратит запасы, ест из рюкзака, может погибнуть
→ сохранить состояние → перепланировать уведомления → отправить аналитику
```

Движок вызывается только при открытом приложении: Dart в фоне не запускается. Фоновая Kotlin-задача копит шаги, а уведомления о голоде, холоде и ждущем событии заранее рассчитываются при закрытии приложения и ставятся в расписание (см. §6).

## 5. Остановки (почему игроку нужно возвращаться)

Герой идёт сам, пока не дойдёт до остановки. На остановке ждёт игрока, а шаги копятся в буфере и не пропадают:

* **Событие** — карточка с выбором.
* **Город или деревня** — привал: тепло восстанавливается, открыт рынок, кнопка «Идти дальше».
* **Конец главы** — финальная карточка главы.
* **Задержка** — событие «пережидаем бурю 6 часов»: герой стоит по реальному времени.

## 6. Уведомления (локальные)

Kotlin планирует через WorkManager по списку, который Dart пересчитывает при каждом открытии и закрытии:

* утренняя мысль — каждый день в выбранное время (по умолчанию 8:00), на 7 дней вперёд;
* 1–3 событийных в день: «На пути что-то случилось» (если есть ждущая остановка и игрок не открывал приложение 3+ часа), «Сергей мёрзнет / голоден» (если показатель ниже 40 — днём в 13:00), «Задержка закончилась»;
* тихие часы 22:00–08:00, не больше 3 событийных в день.

## 7. Хранение и приватность

* Состояние героя, журнал, ответы на утренние мысли — JSON в SharedPreferences на телефоне. Никуда не отправляются.
* Профиль: имя, почта, согласие. В AppMetrica почта уходит только как ID профиля и только при согласии; тексты ответов — никогда.
* Ключ AppMetrica — `--dart-define=APPMETRICA_KEY=...` из секрета GitHub. Нет ключа — аналитика пишется только в локальный журнал (экран «Настройки → Журнал аналитики» для отладки).

## 8. Сборка

GitHub Actions:
1. `tools/map/build_map.py` скачивает Natural Earth и строит линию маршрута через OSRM → `assets/map/map.json` (при сбое остаётся резервная карта из репозитория);
2. `flutter create` генерирует `android/`, `tool/bootstrap_android.sh` накладывает `android-overlay/` (Kotlin, манифест, зависимости, minSdk 26);
3. `flutter build apk --release` → артефакт `putnik-test.apk`.

## 9. Что переиспользовано и что заморожено

* Бэкенд этапа 0 (`backend/`) заморожен до возвращения сервера; правила зачёта шагов перенесены в клиент.
* Каталог московских маршрутов, демо-лимит и демо-подписка удалены.

## 10. Дополнения после ревью и приёмки

* Подпись: все тестовые сборки подписаны одним ключом `app/android-overlay/putnik-test.jks`, номер сборки растёт с каждым запуском CI — обновления ставятся поверх без потери прогресса. Для RuStore будет отдельный ключ.
* Карта онлайн: суша из `ne_10m_land` (фон — море); резервная карта: море поверх суши.
* Фоновое чтение датчика может блокироваться системой (Android 9+ для фоновых приложений): шаги не теряются, а засчитываются при открытии. Health Connect даёт точные дни.
* Лимит событийных уведомлений учитывает уже показанные за день (хранится на телефоне).
* Финал главы показывается один раз; после смерти с откатом город — обычный привал.
